# ChatGPT long-conversation performance tools

> Copied from the local comparison workspace. Links into `research/` and the unpacked extension folders point to third-party code and store snapshots that are not in this repository. Benchmark results for these extensions are in [REPORT.md](REPORT.md#47-和其他扩展对比).

Survey date: **2026-10-29** (America/Toronto). Source and store snapshots are saved under [research/](research/). This is a source review and packaging exercise, not a performance benchmark or a live compatibility test. No browser installation, login, or visit to chatgpt.com was performed. `~/.local/share/chatgpt-lab/` was not accessed.

## Findings that affect the benchmark

- **Most fixes target an older problem.** The supplied live-DOM observation says ChatGPT already unmounts old turns, leaving roughly 4–5 mounted, while one math-heavy turn can still contain ~20,000 nodes. Hiding everything except the last 8, 10, or 30 messages may do nothing in that state. The supplied profile attributes 50–67% of streaming main-thread time to Recalc Style and less than 1% to layout; this is the task's evidence, not a measurement reproduced here.
- **The most relevant new discovery is CJ-tpub's interaction optimizer**, updated today. It suppresses redundant `data-dil-message-id` writes and coalesces page MutationObserver/ResizeObserver callbacks. This targets repeated browser work more directly than deleting history, although the exact hot attribute must be present for its attribute guard to help. It also has substantial display-layer and streaming-detection caveats. [Source](long-chat-smooth/chatgpt-long-chat-smooth.user.js)
- **LightSession Pro's default branch predates the current API adaptation.** Its built source handles singular `/backend-api/conversation/:id` and mapping trees; open [PR #44](https://github.com/11me/light-session/pull/44) proposes plural `/backend-api/conversations/:id` and flat `messages` support. Do not conclude that a successful build means it actually trims current payloads. [Interceptor](light-session/extension/src/page/page-script.ts)
- **Two well-known store products no longer provide the original fix.** ChatGPT Performance Long Chats explicitly disabled its optimizations; Sebastian Tirelli's LightSession replaced trimming with a separate reader/search interface. These are unsuitable active lag-fix baselines in their current versions. [Performance Long Chats listing](https://chromewebstore.google.com/detail/mbnpogfcgjbhfbpelaidnnaodkhoehjd), [LightSession listing](https://chromewebstore.google.com/detail/fmomjhjnmgpknbabfpojgifokaibeoje)
- **No inspected candidate implements actual token/SSE delivery throttling.** GPT Performance Optimizer rewrites conversation mappings found in stream chunks, but does not batch token delivery on a timer. Lazy Chat++ pauses its own work while streaming; it does not throttle ChatGPT's rendering. [Stream hooks](gpt-optimizer/extention/core/stream-hooks.js), [Lazy Chat++](lazy-chat/lazy-chat-plus-plus.user.js)

## Mechanics and limitations

### ChatGPT Lag Fixer (bramvdg)

[`src/constants.js`](lag-fixer/src/constants.js) defines one legacy article selector. [`src/virtualization.js`](lag-fixer/src/virtualization.js) assigns IDs, measures heights, keeps actual original nodes in `state.articleMap`, and `replaceWith`s transparent spacer divs; restoration uses the retained node, rather than recreating React components. Scrollable-ancestor detection can theoretically find `.thread-scroll-container`, but cannot start from a nonexistent article. Streaming protection checks `[data-testid="stop-button"]` and skips virtualization. No current TALVT, KaTeX, or ProseMirror optimization exists. The repository's [README](lag-fixer/README.md) identifies the current commercial successor; the public code remains the legacy implementation. The actual [LICENSE](lag-fixer/LICENSE) is PolyForm Strict and prohibits modification/distribution under its grant, despite `package.json` saying MIT; this checkout was left unchanged. The saved open-issues API response contained no open items, which does not demonstrate working compatibility.

### LightSession / LightSession Pro (11me)

[`page-inject.ts`](light-session/extension/src/content/page-inject.ts) injects a web-accessible page script at document_start and synchronizes settings. [`page-script.ts`](light-session/extension/src/page/page-script.ts) patches fetch only for GET singular conversation/shared_conversation URLs and JSON payloads with `mapping/current_node`; it also has bootstrap synchronization via a conversation refetch. [`trimmer.ts`](light-session/extension/src/shared/trimmer.ts) walks the active branch, counts role transitions rather than raw nodes, and repairs mapping/root links. This is before-React state reduction, not simple DOM deletion and not SSE throttling. [`chat-view.ts`](light-session/extension/src/content/chat-view.ts) uses role/message-id fallbacks for UI counting; [`user-collapse.ts`](light-session/extension/src/content/user-collapse.ts) depends on user role/id roots, `.user-message-bubble-color`, and markdown/text classes. These nested attributes were not included in the supplied contract. Open [PR #44](https://github.com/11me/light-session/pull/44) specifically addresses the plural endpoint/flat messages; it was not merged or applied here. Other open reports cover [missing Drive confirmation UI #42](https://github.com/11me/light-session/issues/42), [branching #41](https://github.com/11me/light-session/issues/41), and [remaining CPU/animation cost #36](https://github.com/11me/light-session/issues/36). “Ultra Lean” currently toggles `ls-ultra-lean` in [`content.ts`](light-session/extension/src/content/content.ts), but no matching CSS rules were found in this checkout; do not credit README animation/containment claims as implemented behavior. The default branch is 1.7.4 even though the stores advertise 1.7.5; the benchmark must record that version difference.

### GPT Delagger

[`content.js`](delagger/content.js) discovers message blocks from `[data-message-author-role]`, climbs to an ancestor holding only one message while avoiding composer-containing roots (`form,textarea,[contenteditable="true"]`), and adds its own `data-gptdelag-turn` attributes. It applies CV/intrinsic height, `data-gptdelag-old` display hiding, tool/embed filtering, and global transition removal; backdrop blur removal is opt-in. Default trimKeep is 30. It deliberately retains React-owned nodes: the [changelog](delagger/CHANGELOG.md) explains that pre-1.6 detachment broke React reconciliation/click handlers. It scans recent tool content and uses before-paint mutation handling; this is not React/token-update throttling. It is a good CSS control if role attributes remain present, but 30-turn trimming will be inactive in a 4–5-turn native window. Open [#5](https://github.com/throwingogo-hub/chatgpt-delagger/issues/5) requests proper regression measurements; [#4](https://github.com/throwingogo-hub/chatgpt-delagger/issues/4) confirms CWS publication is still pending. Its offline fixture results are not live ChatGPT latency results.

### ChatGPT Thread Optimizer

[`src/content.js`](thread-optimizer/src/content.js) observes body mutations and schedules optimizer passes with requestAnimationFrame. It detects old test IDs or role-containing articles, tags detected turns, and parks turns older than ten when their text exceeds 220 characters. [`src/content.css`](thread-optimizer/src/content.css) hides their children and supplies a fixed 78px preview using pseudo-elements; no actual DOM unmount or history-fetch rewrite occurs. It applies CV to detected turns and optionally `pre`, `table`, and markdown-heavy blocks. This could affect visible heavy blocks after selector adaptation, but stock source has no `div[data-turn-key]` fallback. No open issues were returned. The source was preserved as a loadable native extension and a likely inactive baseline.

### ChatGPT Lazy Chat++

[`lazy-chat-plus-plus.user.js`](lazy-chat/lazy-chat-plus-plus.user.js) has `MODE = 'hide'` and an eight-turn visible batch, despite README claims that detach is the default. Alternatives replace nodes with placeholders or add a CV class. Idle-batched maintenance and token estimation pause when Stop-button selectors indicate streaming; a 500ms poll and 500ms end cooldown remain. This reduces its own interference and does not reduce ChatGPT stream frequency. All turn selectors are legacy test IDs or article-specific data-turn attributes, not `data-turn-key`. Scroll-root derivation is heuristic. The script also intercepts copy/cut propagation and modifies `/translate` layout; these side effects should be recorded if used outside the target chat workload. Its open [issue #1](https://github.com/AlexSHamilton/chatgpt-lazy-chat-plusplus/issues/1) proposes improvements, rather than proving current compatibility. The wrapper preserves the exact script bytes, including stock defaults.

### ChatGPT Web Long Chat Interaction Optimizer (CJ-tpub)

[`chatgpt-long-chat-smooth.user.js`](long-chat-smooth/chatgpt-long-chat-smooth.user.js) contains several distinct layers. `installAttributeGuard` patches setAttribute/setAttributeNS and skips same-value writes only for `data-dil-message-id`. `installDamper` wraps newly constructed page MutationObservers, coalescing wide or >20-callback/s observers to 100ms deliveries, and >30-callback/s ResizeObservers to 80ms; it caps pending mutation records at 10,000. **This changes observer delivery semantics and can drop older queued records**, so treat functional correctness as part of the benchmark. It is not token-stream pacing. Its document_start MAIN-world wrapper is necessary for these patches to affect page code.

The same script finds turns via `[data-chatgpt-search-unit-key], [data-testid^="conversation-turn-"]`, not `data-turn-key`. It derives scroll roots by overflow and has a `.thread-scroll-container` fallback. Historical CV skips ancestors already marked `[data-virtualized-turn-content]`. It hides old assistant answers behind measured-height placeholders and hides the original newest stable answer while displaying a cloned “twin”; block CV applies to sufficiently tall/high-child-count containers inside that clone, without a KaTeX-specific selector. Focus mode temporarily parks other answers when editing controls within an answer; the optional composer layer is disabled by default. Streaming detection uses aria-busy and legacy result/streaming attributes/classes, **not `[data-talvt-turn-state="in_progress"]`**, so the twin could be created at an unsafe time on the supplied UI. Citation clicks restore the original before forwarding; stateful inputs prevent cloning. Native unmounting/content growth can interact with this display layer. The [README](long-chat-smooth/README.md) documents prior rebuild loops and broken controls; its reported improvements are author claims, not reproduced results. No open issues were returned. License is noncommercial; do not classify this as MIT/GPL software.

### GPT Performance Optimizer

[`core/optimizer.js`](gpt-optimizer/extention/core/optimizer.js) trims mapping history before React and stores flattened full history in localStorage; [`core/stream-hooks.js`](gpt-optimizer/extention/core/stream-hooks.js) additionally patches getReader/read, EventSource listeners and bootstrap scripts to rewrite chunks containing mappings. It processes each read independently and does not implement a cross-chunk SSE/frame buffer or delivery throttle, making split JSON/UTF-8 boundaries a source-level concern. [`ui/toolbar.js`](gpt-optimizer/extention/ui/toolbar.js) and [`theme/clx-theme.js`](gpt-optimizer/extention/theme/clx-theme.js) recreate historical messages outside React using Markdown/highlighting, rather than the original rich ChatGPT tree. This is a poor fidelity control for KaTeX, attachments, and interactive answers. [`ui/loader.js`](gpt-optimizer/extention/ui/loader.js) waits for `#thread`, `div.flex.flex-col.text-sm`, and old articles; the last condition fails against the supplied turn DOM and the loop times out after 30 one-second checks. Open [PR #2](https://github.com/sergey-pimenov/gpt_performance_optimizer/pull/2) addresses the 30-second loading freeze. Its unmodified `extention/` directory is structurally loadable, but the repo has no project LICENSE or package license declaration; public visibility and the store's “open-source” wording do not establish an open-source grant. Kept as a supplementary architecture reference, not a primary licensed recommendation.

### ChatGPT In-Memory Conversation Trimmer (GF 561766)

[`research/sources/561766.user.js`](research/sources/561766.user.js) wraps page fetch, broadly matches URLs containing “conversation”, checks application/json, walks backward from current_node, keeps the last 40 raw mapping nodes, removes dangling child links and sets the oldest retained parent to null. Load older adds 20 and reloads; full history is a one-reload bypass. This is a small licensed before-React control with no ChatGPT turn selectors. It does not understand flat `messages`, does not pace streams, and does not count user/assistant role transitions; on modern paginated responses it may simply have nothing to trim. The wrapper supplies its only userscript dependency, `unsafeWindow`, as a function parameter receiving page `window`; no optimizer logic was changed.

### ChatGPT Smooth Scroll (Anti-Lag)

[`research/sources/570347.user.js`](research/sources/570347.user.js) injects CV, layout/style/paint containment, and a 300px intrinsic-height fallback on old section/testid turns. IntersectionObserver stores measured visible heights and MutationObserver registers newly inserted sections. It retains DOM and state and does not alter streaming. The old section selector makes it an inactive control on the supplied turn structure; it was downloaded for inspection rather than packaged.

### GPT Optimum

The reviewed [GF 2.2 source](research/sources/570759.user.js) is newer than the [GitHub 2.1 snapshot](research/sources/GptOptimum/GptOptimum.js). It discovers role roots plus generic articles/legacy classes, measures their heights, and uses IO to toggle `content-visibility:hidden`; it does **not** unmount those nodes despite “unload” marketing. It adds settings/status UI and an input blocker during optimization. Broad overlapping selectors, a busy-state workflow, and GM_getValue/GM_setValue/GM_addStyle dependencies make it a less clean benchmark than Delagger. Role matching is conditional on nested DOM absent from the task contract. No performance claim was accepted from its README.

### ChatGPT Lazy Loader + Extended Thinking

[`research/sources/598790.user.js`](research/sources/598790.user.js) targets role nodes, creates previews, and detaches or hides their bodies. Default `collapseMode = 'detach'`, `keepExpandedLast = 0`; the last two roots are protected while a Stop button is present. It also opens composer/model menus to set Thinking behavior, introducing a separate feature and unrelated UI work. React-owned child movement and the unverified stop selector make it lower priority; no TALVT state or token pacing is implemented. GM_addStyle has an in-script fallback, but this script was not chosen for an unpacked wrapper.

### ChatGPT Conversation Pruner

[`chatgpt-conversation-pruner.user.js`](research/sources/ChatGPT-Conversation-Pruner/chatgpt-conversation-pruner.user.js) waits for stable DOM samples, keeps eight live section/testid turns, removes older elements into a per-conversation cache capped at 300, and restores batches through a scroll sentinel/IO. It hides rather than removes in detected voice modes. Cache eviction and physical React DOM removal are tradeoffs; its stable-DOM heuristic is not an explicit TALVT stream-state check. The section selector fails the supplied DOM and the eight-turn default may exceed native mounted content even after adaptation.

### ChatGPT Virtual Scroll (9ghtX)

[`chatgpt-virtual-scroll.user.js.js`](research/sources/ChatGPT-Virtual-Scroll/chatgpt-virtual-scroll.user.js.js) is the actual upstream filename. It prunes section/testid turns into memory and compensates scroll anchors while restoring; it also injects CV CSS. The reviewed source's MAX_TURNS is **2**, not the README/search excerpt's 4–6. Scroll detection prefers `[data-scroll-root]`, then heuristics. This is an aggressive old-DOM virtualizer with potential React and scroll-position interactions, so no wrapper was prepared.

### Trimwise (icedmoca fork)

The reviewed [performance-refactor content.js](research/sources/Trimwise/content.js) waits for old article counts to stabilize, uses separate IO buffers for offscreen removal/restoration, retains original nodes in a Map, and replaces them with measured-height placeholders. It also collapses long user messages. This is distinct from an innerHTML clone, but still manipulates React-owned nodes and assumes obsolete article/testid turns. Upstream README speed/memory percentages and changelog dates were not treated as measured facts. The fork's [repo metadata](research/Trimwise-repo.json) identifies its parent as garanovich/Trimwise; this survey did not conflate parent and fork revision dates.

### Hopex ChatGPT DOM Pruner

[`main.js`](research/sources/chatgpt-dom-pruner/main.js) targets user/assistant articles with `data-turn`, keeps recent content live, marks middle-range turns `content-visibility:hidden` with an approximate intrinsic height, and permanently removes very old or apparently empty turns. Its empty-turn test clones and strips controls before checking meaningful content. No project license was detected in the saved GitHub metadata, and its hard deletion/obsolete article selectors make it a weak current comparator. No Chrome package was prepared.

### Xeloan ChatGPT-Optimizer

[`content.js`](research/sources/Xeloan/content.js) locates `.markdown` ancestors with class strings containing `group`, saves original innerHTML in data attributes, substitutes a height-matched wrapper containing invisible plain text, and reconstructs the HTML on restoration. IO plus a 1.5-second sweep keeps the last three messages visible. This destroys/recreates descendant DOM and event handlers; the [README](research/sources/Xeloan/README.md) acknowledges broken code-copy buttons after restoration. Neither the markdown/group selectors nor control fidelity are established by the supplied contract. GitHub detects GPL-3.0 while README restrictions forbid commercial use and redistribution; the terms are inconsistent, so no derived package was made.

### ChatGPT Long Conversation Helper (OnerGit)

[`chatgpt-long-conversation-helper.user.js`](research/sources/ChatGPT-Long-Conversation-Helper/chatgpt-long-conversation-helper.user.js) finds user/assistant role roots, wraps content with collapse controls, injects three-line height/overflow CSS and a fade mask, and remembers local UI state. It observes main/body with debounced scans. This chiefly changes readability and visible height while retaining content; it has no fetch rewrite, token pacing, or math-specific treatment. Role attributes are conditional on additional DOM, and simply clipping a large live answer is less relevant than suppressing its repeated style invalidation.

### ChatGPT Long Chat Booster (mrkwxopya)

[`chatgpt-long-chat-booster.user.js`](research/sources/mrkwxopya/chatgpt-long-chat-booster.user.js) discovers old articles first, then falls back to role nodes or generic articles. It adds classes for old/collapsed turns, configures code/table sizes, lazy media loading, sidebar CV and motion reduction. The fallback is more permissive than its CSS: many principal rules still target `main article`, so discovering a new div does not guarantee effective collapse. Its default 18 recent turns exceeds the supplied native window. The GitHub source is 2.0.1; a Greasy Fork metadata request was blocked, so no GF update date or install count is asserted.

### ChatGPT SpeedFix (AMO)

The published MPL-2.0 XPI's [`pageScript.js`](research/sources/amo-chatgpt-speedfix/pageScript.js) wraps fetch, detects singular conversation URLs while explicitly excluding plural conversations URLs, and reconstructs a recent mapping path. [`content.js`](research/sources/amo-chatgpt-speedfix/content.js) inserts a reload-based Load older button before old article/testid nodes. Default is 15 messages. Its network technique survives a purely cosmetic DOM change, but not a schema/endpoint migration; the history button does not select the supplied new turn divs. There is no linked source repository in the saved AMO API response, so the published readable XPI was used as the primary source and retained for inspection only.

### ChatGPT Lag Fixer (AMO, ilikepeanutbutter)

The MIT-listed XPI's [`content.js`](research/sources/amo-chatgpt-lag-fixer/content.js) queries old articles every three seconds, shows the newest configured batch with display changes, and recreates a Show more button. Its actual source default is 20, while the store description says 50; settings can override it. It neither releases React state nor prevents cold loading. The turn selector fails the supplied DOM. Its [AMO metadata](research/amo-chatgpt-lag-fixer.json) belongs to a different author/product than bramvdg's similarly named extension.

### ChatGPT Performance Long Chats

The [current first-party listing](https://chromewebstore.google.com/detail/mbnpogfcgjbhfbpelaidnnaodkhoehjd) says its previous optimizations “have been disabled to avoid conflicts with ChatGPT's native behavior.” Historical search results describe initial history limits and automatic collapse/reveal, but source was not found on the listing or through exact-name/id/publisher GitHub searches; those older claims cannot establish current implementation. License and selectors remain unknown. No CRX mirror or store binary was downloaded.

### Speed Booster Toolkit (closed successor)

The [current listing](https://chromewebstore.google.com/detail/finipiejpmpccemiedioehhpgcafnndo) advertises control over how many older messages load, full-chat loading, navigation, search and export; these are product claims without inspected current source. The legacy repo's [README](lag-fixer/README.md) explicitly distinguishes its old public code from the rewritten successor, and the [AMO metadata](research/amo-chatgpt-speed-booster.json) specifies All Rights Reserved. It was noted but **not downloaded**, including no XPI download. Benchmarking the legacy repo cannot substantiate claims about Toolkit 4.6.1.

### LightSession (Sebastian Tirelli, separate product)

The [author's original technical account](https://sebastiantirelli.com/writing/chatgpt-lightsession/) describes a fetch wrapper reconstructing the recent active mapping chain before React and documents its September 2026 replacement with reader/search. The [current store listing](https://chromewebstore.google.com/detail/fmomjhjnmgpknbabfpojgifokaibeoje) explicitly says trimming is gone because ChatGPT now paginates natively. This product is not the 11me MIT repository. No current public source was found; current selectors cannot be audited and it was not downloaded.

## Benchmark priority

1. **CJ-tpub interaction optimizer**, first for mechanism relevance. Compare streaming and composer latency with the stock MAIN-world script, but verify whether its hot attribute actually exists and which layers activate. Its same-value-write guard and observer coalescing may reduce style-related work even when old-turn trimming has nothing to remove. Track final text, math, citations, selection and input correctness because its observer semantics/static twins are invasive. Its missing TALVT streaming detection is a concrete concern, not a reason to assume success.
2. **GPT Delagger**, best clean CSS/role-based control. Compare defaults, liteRender alone, and noTransitions/noBlur toggles separately. Keep trim count visible in the record: a zero-hidden-turn result with native windowing still tests CSS/tool work, not trimming effectiveness.
3. **LightSession Pro**, best licensed pre-React hypothesis, conditional on activation. Record endpoint, response shape, and actual before/after message counts. Stock 1.7.4 may miss the plural/flat API; report that as incompatible rather than “no speedup.” The open PR could later be tested as a distinct variant, but was not applied here.
4. **GF In-Memory Trimmer**, a small supplementary network control. Useful only when the legacy mapping payload is present; it tests how much keeping less client history matters beyond ChatGPT's own DOM windowing. It does not reduce math nodes within the active answer.
5. **Legacy Lag Fixer, Lazy Chat++, and Thread Optimizer**, low-priority compatibility/negative controls. They are packaged because they are prominent or easy to compare, but their stock selectors do not select the supplied turn divs. Do not spend latency runs on them until an activation check passes. Patching them would test a port, not the downloaded upstream version.
6. **GPT Performance Optimizer**, architecture reference rather than first benchmark: no project license, stale loader/history DOM, potential 30s overlay, rich-content fidelity differences, and global chunk hooks make it a noisy comparator. It is the only inspected candidate with broad stream hooks, but **those hooks trim history; they do not throttle token delivery**.

For later runs, use one extension at a time and identical response replay/math content. Separate cold conversation load, settled scroll/typing, and live-stream typing; record Recalc Style, script time, long tasks, dropped frames, mounted turn/node counts, actual optimizer activation, and content integrity. Given the supplied <1% layout share, a lower layout count alone would not establish a fix for the observed bottleneck. Include the unmodified ChatGPT/native-windowing baseline and the team's own style-invalidation fix. This survey makes no runtime speedup claim.
