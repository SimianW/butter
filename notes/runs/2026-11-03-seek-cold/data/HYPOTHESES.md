Ranked, falsifiable hypotheses (from user-provided evidence, tested independently):

1. Replacing a never-measured row's estimated height breaks the pixel promise. If a semantic text/message anchor is frozen at release and retargeted after mount, the previewed turn and selected text should align even when total scroll height changes.
2. Cold mounting cost comes from layout that saved per-block intrinsic sizes could avoid. If geometry is restored across a reload before React forces layout, release time should approach the in-document warm path. Stored geometry alone cannot change native thumb mapping.
3. Text length misses the large contribution from display-math/blocks. If structure and available column width matter, unseen-row estimate error should fall against measured heights; this need not fix native mapping because the application still estimates independently.
4. A direct virtualizer height write might unify native mapping, but the state is duplicated. A state-only write can be overwritten by a layout effect. A lab-only coupled ref/dispatch probe was prepared with exact asset/source/hook/queue gates. Actual run `runs/inject-study.json` returned `why=asset`, `writes=0`, despite the expected source SHA. Native height and the five ever-mounted turns stayed unchanged. This is a fail-closed refusal, not proof of feasibility or impossibility.
